# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## What this is

A full-stack proof-of-concept for a blockchain-anchored land covenant registry targeting county government. Three independent packages: `contracts/` (Solidity/Hardhat), `backend/` (Express/SQLite), `frontend/` (React/Vite). No monorepo tooling — each package has its own `node_modules` and must be installed separately.

## Commands

**Contracts** (run from `contracts/`):
```bash
npm run compile          # compile Solidity
npm run node             # start local Hardhat node on :8545 (keep running)
npm run deploy:local     # deploy to local node → writes backend/contract-address.json
npm run deploy:baseSepolia  # deploy to Base Sepolia testnet
npm test                 # run contract tests
```

**Backend** (run from `backend/`):
```bash
npm run seed   # mint all 50 parcels + add pre-seeded covenants; idempotent
npm start      # start API server on :3001
npm run dev    # same with nodemon hot-reload
```

**Frontend** (run from `frontend/`):
```bash
npm run dev    # Vite dev server on :5173, proxies /api → :3001
npm run build  # production build to dist/
```

**Required startup order**: `hardhat node` → `deploy:local` → `seed` → `npm start` (backend) → `npm run dev` (frontend).

## Architecture

### Data flow

The chain is the source of truth for covenants; SQLite is a queryable cache enriched with off-chain metadata (coordinates, `flagged` status, owner type). The backend syncs chain events into SQLite on demand — `GET /api/audit/:apn` triggers a live `queryFilter` call that upserts any missing events.

When a covenant is added via `POST /api/parcels/:apn/covenant`, the backend:
1. Calls `contract.apnToId(apn)` to get the uint256 parcel ID (keccak256 of APN string)
2. Calls `contract.addCovenant(parcelId, ...)` — signed by the deployer wallet (no user wallet required)
3. Waits for 1 confirmation, then writes to SQLite and returns `{ txHash, blockNumber, ipfsHash }`

### Contract → backend coupling

`chain.js` reads two files at startup:
- `contracts/artifacts/.../CovenantRegistry.json` — ABI (generated by `npm run compile`)
- `backend/contract-address.json` — deployed address (generated by `npm run deploy:*`)

If either is missing, the backend starts in SQLite-only mode (gracefully degraded, logs a warning). The seed script fails hard if `contract-address.json` is missing.

### Nonce management

The backend wallet is wrapped in `ethers.NonceManager` to prevent nonce collisions when sending sequential transactions in Hardhat's automining mode. Always use `await wallet.getAddress()` — not `wallet.address` — since `NonceManager` doesn't expose `.address` directly.

### Route ordering

In `parcels.js`, the `/search` route **must** be defined before `/:apn` or Express will interpret `search` as an APN. This ordering is load-bearing.

### Frontend state

All view state lives in `App.jsx` — no external state library. The panel stack is controlled by three booleans/objects: `selectedParcel`, `showAudit`, and `showAddCovenant`. Demo mode advances `demoStep` (1–5) automatically on user actions (parcel select → step 3, add covenant → step 5, etc.).

The `parcels` array (loaded once from `GET /api/parcels`) holds summary rows with `active_covenant_count` and `flagged_count` for map coloring. Full covenant details are only fetched when a parcel is selected.

### Map marker colors

Determined by fields on the summary parcel row: `flagged_count > 0` → amber `#F59E0B`; `active_covenant_count > 0` → slate blue `#4A6FA5`; otherwise gray `#9CA3AF`.

### "Blockchain" mention constraint

The word "blockchain" appears exactly once in the UI — inside the `Navbar.jsx` info tooltip triggered by the `<Info>` icon. Do not add it anywhere else. All user-facing copy uses "Secure Registry", "cryptographically secured", or "tamper-proof record".

## Key files

| File | Purpose |
|------|---------|
| `contracts/contracts/CovenantRegistry.sol` | On-chain append-only covenant store |
| `backend/src/chain.js` | ethers v6 provider/wallet/contract singleton |
| `backend/src/db.js` | SQLite schema init (runs on require) |
| `backend/src/seed.js` | One-time data seeder — 50 Marin County parcels + 21 covenants |
| `backend/src/routes/parcels.js` | All parcel CRUD including chain writes |
| `frontend/src/api.js` | Typed fetch wrapper for all backend endpoints |
| `frontend/src/App.jsx` | Root state and panel visibility logic |
| `backend/contract-address.json` | Generated — do not commit to production branches |

## Environment

`backend/.env` is gitignored. Copy from `.env.example`. The default `DEPLOYER_PRIVATE_KEY` is Hardhat account #0 — safe only on local testnet. For Base Sepolia, replace with a funded key and set `HARDHAT_NODE_URL=https://sepolia.base.org`.

Node.js 25 is in use; Hardhat prints a warning about unsupported versions but works. `better-sqlite3` requires v12+ for Node 25 prebuilt binaries.
